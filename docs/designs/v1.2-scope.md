## P2 sketch — approval-request file protocol

1. Executor env gains `DSH_APPROVAL_FILE=<worktree>/.dsh/approval-request.md`; agent
   prompts (executor template) may mention it: "to ask the owner, write title + reason +
   requested action to this file and stop".
2. `runWork` post-run check: file exists → ticket goes `needs-person` with the file's
   title/reason as the structured request; file is consumed (moved to
   `.dsh/approval-requested/`); a normal approval request renders in the ops thread.
3. Existing digit routing decides (1 approve-resume / 2 stop / 3 detail); "approve" means
   *resume with this note as guidance*, never a capability token — same rule as LofiSu's
   no-token stance, but ours is enforced by the file being one-way (worker writes, engine
   reads; nothing the worker writes can flip a gate by itself).
4. Failure mode: worker writes garbage → assessment still one call; worst case a needs-person
   the owner discards with "2". Annoying, not dangerous.
